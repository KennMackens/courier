# Linear Idea Capture

## Overview

Guide the user through a short, structured conversation to capture a feature idea, then create a draft Linear ticket with a clear title and initial acceptance criteria.

## Workflow

1. Ask guided questions one at a time.
- Core Idea: What’s the feature or improvement? (brief description)
- Problem: What problem does this solve for users?
- Type: Is this a new feature, enhancement, or bug fix?
- Priority: Low, Medium, High, or Urgent?

2. Summarize and propose a ticket.
- Summarize the idea clearly.
- Suggest a concise, actionable title.
- Draft a structured description using the template below.

3. Confirm with the user.
- Show the proposed ticket content.
- Ask for confirmation before creating the issue.

4. Create the Linear ticket.
- Use the appropriate team (ask if unknown).
- Add the correct tag/label if the workspace uses idea tags.
- Set the status to the `idea` group/status (ask for the correct status name if unknown).
- Provide the ticket number and URL.

## Ticket Description Template

**Problem/Context**
- The user need or issue

**Proposed Solution**
- What we’ll build

**Acceptance Criteria**
- Draft criteria, can be refined later
- Keep each criterion verifiable

## Notes

- Keep the conversation focused and lightweight; this is a first draft.
- If the user is unsure, record as `TBD` or in an open question.
- Use Linear MCP tools for issue creation.
